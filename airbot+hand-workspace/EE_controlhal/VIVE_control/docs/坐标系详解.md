## 坐标系概览

本系统涉及 **4 个主要坐标系** 和 **6 个转换步骤**：

| 序号 | 坐标系名称 | 原点位置 | 用途 |
|------|-----------|---------|------|
| 0 | OpenXR Stage | 房间固定点 | VR 基站物理追踪 |
| 1 | teleop_standard | 房间固定点 | 设备无关的统一表示 |
| 2 | body_standard | 身体位置 | 相对操作者，走动不影响机器人 |
| 3 | robot_base | 机器人基座 | 机器人控制目标 |

## 详细转换流程

### 步骤 0：libsurvive 原始数据（OpenXR Stage）

**坐标系定义**：
```
        +Y (上)
         ↑
         |
-X (左) ←O→ +X (右)
        /
       /
     -Z (前)    +Z (后)
```

**关键点**：前方是 **-Z**（负 Z），这是 OpenXR Stage 标准。

**数据示例**：
```python
body_tracker = {
    position: [0.0, 0.0, 0.0],      # 身体在房间中央
    rotation: [qx, qy, qz, qw]
}

hand_tracker = {
    position: [0.3, 1.2, -0.5],     # 右 0.3m, 上 1.2m, 前 0.5m
    rotation: [qx, qy, qz, qw]
}
```

---

### 步骤 1：转换到 teleop_standard（vr_normalize）

**目标坐标系**：
```
        +Z (上)
         ↑
         |
+Y (左) ←O→ -Y (右)
        /
       /
     +X (前)    -X (后)
```

**转换公式**（代码：`vr_normalize.py:35-37`）：
```python
def openxr_to_teleop_position(position: np.ndarray) -> np.ndarray:
    x, y, z = position  # OpenXR 坐标
    return np.array([-z, -x, y])  # teleop_standard 坐标
```

**映射关系**：
| teleop 轴 | ← | OpenXR 轴 | 说明 |
|----------|---|-----------|------|
| +X (前) | ← | -Z | OpenXR 前方是 -Z |
| +Y (左) | ← | -X | OpenXR 右是 +X，左是 -X |
| +Z (上) | ← | +Y | 上方向相同 |

**数据示例**：
```python
# 输入（OpenXR）
hand_openxr = [0.3, 1.2, -0.5]  # 右 0.3m, 上 1.2m, 前 0.5m

# 输出（teleop_standard）
hand_teleop = [-(-0.5), -(0.3), 1.2]
            = [0.5, -0.3, 1.2]   # 前 0.5m, 右 0.3m, 上 1.2m
```

**姿态转换**（旋转矩阵共轭变换）：
```python
R_new = OPENXR_TO_TELEOP_R @ R_old @ OPENXR_TO_TELEOP_R.T
```

### 步骤 2：建立身体坐标系（head_base）

**问题**：这个房间里，操作者面向 OpenXR +Z（后方），经过转换后变成 teleop -X（后退）。

**解决方案**：应用 180° yaw offset + 相对化。

#### 2a. 构建 180° 旋转矩阵

代码：`head_base.py:51-58`

```python
rotation = np.array([
    [-1,  0,  0],  # X 轴翻转
    [ 0, -1,  0],  # Y 轴翻转
    [ 0,  0,  1]   # Z 轴不变（上方向）
])
```

#### 2b. 位置相对化

代码：`head_base.py:47`

```python
def relative(self, hmd, hmd_valid, hand):
    rotation, origin = self._frame(hmd, hmd_valid)
    # 位置相对化
    p_rel = rotation.T @ (hand.position - origin)
    # 姿态相对化
    r_rel = rotation.T @ matrix_from_quat(hand.rotation)
    return Pose(position=p_rel, rotation=quat_from_matrix(r_rel))
```

**公式详解**：
1. 计算世界坐标偏移：`delta_world = hand_world - body_world`
2. 转到身体坐标系：`p_rel = rotation.T @ delta_world`

**旋转矩阵的列 = body 轴在世界系里的指向**

`R` 由 `np.column_stack((forward, left, up))` 构造（`head_base.py:99`），所以 R 的每一列
就是 body 系的一个轴、用 teleop 世界坐标写出来。180° 时：

| body 轴（角色名） | R 的列 | 在房间里指向 |
|---|---|---|
| body +X = 操作者**前** | `[-1, 0, 0]` | 世界 **-X** |
| body +Y = 操作者**左** | `[0, -1, 0]` | 世界 **-Y** |
| body +Z = **上** | `[0, 0, 1]` | 世界 +Z |

两套坐标系的**轴名**都是 `+X 前 / +Y 左 / +Z 上`（本流水线统一约定），180° 翻转的是这两个轴
**在房间里指向哪一边**：body 的"前"是操作者的前，世界的"前"是标定出来的前，这个房间刚好差 180°。

**数据示例**（操作者面朝世界 -X，手伸向机器人）：
```python
# teleop_standard 世界坐标
body_world = [1.0, 0.5, 0.0]   # 身体：世界 +X 1m, +Y 0.5m, 地面
hand_world = [0.2, 0.7, 1.2]   # 手：在身体的世界 -X 一侧 0.8m

# Step 1: 世界坐标偏移
delta_world = [0.2, 0.7, 1.2] - [1.0, 0.5, 0.0]
            = [-0.8, 0.2, 1.2]  # 世界 -X 0.8m, +Y 0.2m, 上 1.2m

# Step 2: 投影到 body 系（R.T = world→body）
p_rel = rotation.T @ delta_world
      = [[-1, 0, 0],     [[-0.8]      [[0.8]
         [0, -1, 0],  @   [ 0.2]   =   [-0.2]
         [0, 0, 1]]       [ 1.2]]      [1.2]]

# 结果（身体坐标系）
hand_rel = [0.8, -0.2, 1.2]
```

**操作者视角理解**（按 body 系的 `+X 前 / +Y 左 / +Z 上` 直接读，无需二次翻译）：
- `x = +0.8` → 操作者**前方** 0.8m ✅
- `y = -0.2` → 操作者**右侧** 0.2m（+Y 是左，故负值为右）✅
- `z = +1.2` → **上方** 1.2m ✅

反之若算出 `x = -0.8`，那就是字面意思：手在操作者**背后** 0.8m。

### 步骤 3：增量式跟踪（clutch）

**目的**：让操作者可以"松手重来"，工作空间大于手臂活动范围。

#### 按下扳机（Space）

代码：`clutch.py:89-98`

```python
if not self._pressed and deadman >= 0.5:
    self._pressed = True
    self._robot_ref = robot.copy()         # 冻结机器人 TCP
    self._controller_ref = None            # 下一帧记录手的基准
    self._pending_vr = True
```

**时序**：
- **当前帧**：冻结 `robot_ref = [0.30, 0.0, 0.20]`，发送当前 TCP（不动）
- **下一帧**：记录 `controller_ref = [0.8, -0.2, 1.2]`，开始计算增量

#### 扳机按住期间

代码：`clutch.py:144-181`

```python
# 计算增量（身体坐标系）
delta_pos = hand_now - controller_ref
          = [0.9, -0.2, 1.2] - [0.8, -0.2, 1.2]
          = [0.1, 0.0, 0.0]  # 手前伸 10cm（body +X = 操作者前）

# 限幅检查
if norm(delta_pos) > max_delta_position:  # 0.35m
    delta_pos = delta_pos * (0.35 / norm(delta_pos))

# 经过坐标变换（下一步）
delta_pos_robot = command_transform.R @ delta_pos

# 最终目标
target = robot_ref + delta_pos_robot
```

#### 松开扳机

```python
elif self._pressed and deadman <= 0.3:
    self._pressed = False
    self._controller_ref = None
    self._robot_ref = None  # 清空基准
```

机器人不会停止，而是**重复发送最后的目标位置**（100 Hz mode=4）。

### 步骤 4：坐标变换到机器人基座（command_transform）

**当前配置**（`teleop.yaml:44-49`）：
```yaml
transform:
  axis_map:
    x: ["x", 1.0]   # robot_x = +1 × teleop_x
    y: ["y", 1.0]   # robot_y = +1 × teleop_y
    z: ["z", 1.0]   # robot_z = +1 × teleop_z
```

**转换矩阵** = 单位阵（AIRBOT Play 基座与 teleop 对齐）：
```python
R = [[1, 0, 0],
     [0, 1, 0],
     [0, 0, 1]]

delta_pos_robot = R @ delta_pos = [0.1, 0.0, 0.0]
```

**如果基座方向不同**（例如机器人的前是操作者的左）：
```yaml
axis_map:
  x: ["y", 1.0]    # robot 前 ← teleop 左
  y: ["x", -1.0]   # robot 左 ← teleop 后
  z: ["z", 1.0]    # robot 上 ← teleop 上
```

### 步骤 5：工作空间限位（workspace）

**配置**（`teleop.yaml:61-68`）：
```yaml
workspace:
  enabled: true
  stop_on_exceed: false  # 超出时 clamp，不停机
  x: {min: 0.06, max: 0.50}  # 前后可达
  y: {min: -0.22, max: 0.22} # 左右可达
  z: {min: 0.10, max: 0.50}  # 上下可达
```

**Clamp 逻辑**：
```python
def clamp_pose(pose):
    pos = pose.position.copy()
    exceeded = False
    for i, (min_val, max_val) in enumerate(limits):
        if pos[i] < min_val:
            pos[i] = min_val
            exceeded = True
        elif pos[i] > max_val:
            pos[i] = max_val
            exceeded = True
    return Pose(position=pos, rotation=pose.rotation), exceeded
```

**示例**：
```python
# 超出前方限制
target = [0.60, 0.0, 0.20]  # x > 0.50
clamped = [0.50, 0.0, 0.20]  # 贴边界 ✅
# 日志：[TELEOP] workspace clamp → [0.500, 0.000, 0.200]
```

## 常见问题

### Q1: 为什么 OpenXR 的前方是 -Z 而不是 +Z？

**A**: 这是 OpenXR Stage 标准的定义，历史原因来自 OpenGL 的右手坐标系（摄像机默认看向 -Z）。所有符合 OpenXR 标准的设备都遵循这个规定。

---

### Q2: 为什么 `openxr_to_teleop_position` 的公式是 `[-z, -x, y]`？

**A**: 逐轴分析：
- **teleop +X（前）** ← **OpenXR -Z（前）**：取负号得到 `-z`
- **teleop +Y（左）** ← **OpenXR -X（左）**：OpenXR +X 是右，取负号得到 `-x`
- **teleop +Z（上）** ← **OpenXR +Y（上）**：方向相同，直接映射 `y`

---

### Q3: body 系也叫 `+X 前 / +Y 左`，那 180° 到底翻转了什么？

**A**: 翻转的是**轴在房间里的指向**，不是轴的**名字**。

`+X 前 / +Y 左 / +Z 上` 是这条流水线里所有坐标系共用的命名约定（角色名），body 系也遵守，
所以标签看起来一样。区别在于"前"指谁的前：

- **teleop 世界系的 +X** = VR 基站标定出来的"前"
- **body 系的 +X** = **操作者**的前

这个房间里操作者面朝世界 -X，两者刚好差 180°，于是 R = Rz(180°)，它的列告诉你
body +X 落在世界 -X、body +Y 落在世界 -Y、body +Z 不变。

**读数不需要二次翻译**：`R.T @ delta_world` 算完，直接按 body 系的 `+X 前 / +Y 左 / +Z 上` 读。
`x = +0.8` 就是操作者前方 0.8m；`x = -0.8` 就是操作者背后 0.8m。

---

### Q4: 为什么需要 180° yaw offset？

**A**: 因为这个房间里，操作者实际面向 SteamVR +Z 方向（标准后方），如果不加偏移：
```
操作者前伸手 (OpenXR +Z)
  → openxr_to_teleop → teleop -X (后退)
  → 机器人后退 ❌
```

加上 180° 后：
```
操作者前伸手 (OpenXR +Z)
  → teleop -X
  → 180° 旋转 → body +X
  → 机器人前进 ✅
```

---

### Q5: 如果换个房间，怎么调整？

**A**: 只需修改 `head_yaw_offset_deg`：
- 操作者面向 OpenXR -Z（标准前）：`head_yaw_offset_deg: 0`
- 操作者面向 OpenXR +Z（标准后）：`head_yaw_offset_deg: 180`
- 操作者面向 OpenXR +X（标准右）：`head_yaw_offset_deg: -90`
- 操作者面向 OpenXR -X（标准左）：`head_yaw_offset_deg: 90`

---

### Q6: Clutch 为什么要延迟 VR baseline（`delay_vr_baseline=true`）？

**A**: 防止按扳机瞬间手抖导致机器人突然跳动：
- **当前帧**：只冻结机器人位置，命令 = 当前 TCP（不动）
- **下一帧**：记录手的基准位置，开始计算增量

如果不延迟，按下扳机的瞬间，手可能在轻微移动（例如 2cm），机器人会立即跟着动 2cm。

---

### Q7: 为什么 `rotation_scale = 0.0`（姿态不跟踪）？

**A**: 因为手腕上的 tracker 姿态 ≠ 夹爪坐标系，需要标定外参（extrinsics）。在 2026-09-02 的测试日志中，1:1 跟踪姿态导致法兰转到 87°，IK 求解失败。暂时只跟踪位置更稳定。

---

### Q8: workspace 限位和 max_delta 限制有什么区别？

**A**:
- **max_delta**（0.35m）：单次扳机按下的**行程限制**，超出后 clamp 增量
- **workspace**（x: 0.06~0.50m）：机器人**绝对可达范围**，超出后 clamp 目标位置

两者都是软限位，超出后贴边界继续操作，不会停机（除非 `stop_on_exceed: true`）。

---

### Q9: 操作者走动时，为什么机器人不动？

**A**: 因为 head_base 相对化：
```python
hand_rel = rotation.T @ (hand_world - body_world)
```

操作者走动时：
- `hand_world` 和 `body_world` **同时移动**相同距离
- 两者的**差值不变**
- `hand_rel` 不变 → 机器人命令不变 ✅

---

### Q10: 如果机器人基座方向和 teleop 不一致怎么办？

**A**: 修改 `axis_map`。例如机器人的前是操作者的左：
```yaml
axis_map:
  x: ["y", 1.0]    # robot 前 ← teleop 左
  y: ["x", -1.0]   # robot 左 ← -teleop 前
  z: ["z", 1.0]    # robot 上 ← teleop 上
```

只改这里，不要动 `vr_normalize` 或 `head_base` 的代码。

---

## 总结

本系统的坐标转换链设计精巧，遵循以下原则：

1. **分层设计**：每个坐标系负责一个职责
   - OpenXR: 物理追踪
   - teleop_standard: 统一表示（设备无关）
   - body_standard: 相对操作者（走动不影响机器人）
   - robot_base: 机器人控制

2. **正交变换**：每一步独立，便于调试和迁移
   - VR 设备换了？只改 `vr_normalize`
   - 房间布局变了？只改 `head_yaw_offset_deg`
   - 机器人方向不同？只改 `axis_map`

3. **增量式控制**：clutch 机制让操作者可以"松手重来"
   - 工作空间大于手臂活动范围
   - 按扳机冻结，只跟踪相对运动
   - 松开扳机，机器人定格在最后位置

4. **安全限位**：多层保护
   - `max_delta`: 单次行程限制（0.35m）
   - `workspace`: 绝对可达范围
   - 软限位：超出后 clamp，不停机
